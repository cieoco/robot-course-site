## 這堂課要完成什麼？

讓一顆馬達依序「轉一秒 → 停止」，然後親眼比較不同 PWM 數字帶來的差異。這是開迴路控制：你指定的是**出力比例**，不是保證的速度。

> **先做安全準備**：把輪子架空，或讓機構有足夠空間活動；第一次從 30% 開始。確認馬達驅動板有外接電源，而且外接電源 GND 與 ESP32 GND 共地。ESP32 的 USB 電源不能當馬達電源。

## 01　打開積木程式頁

手機連上控制板的 Wi-Fi 後，開啟 `http://192.168.4.1`，從主選單進入「🧩 積木程式」。先確認頁面顯示 WebSocket 已連線。

左側是積木工具箱，中間是工作區；頁面最上方的藍色按鈕分別是「停止程式」與「執行程式」。開啟時，工作區已經準備好 `setup` 與 `loop` 兩個骨架。

這一課會用到兩個分類：

| 分類 | 要用的積木 |
| --- | --- |
| Arduino | `setup`、`延遲` |
| 馬達模組 | `馬達 … 方向 … 動力 … %`、`停止馬達` |

## 02　組出第一個動作

從 Arduino 拖出一個 `setup` 積木，依序接上以下三個積木：

1. 從「馬達模組」拖出 `馬達 1 方向 Forward 動力 30 %`。
2. 從「Arduino」拖出 `延遲 1000 毫秒`。
3. 從「馬達模組」拖出 `停止馬達 1`。

`setup` 只會在程式載入後跑一次，所以這正好是一個安全的首次測試：馬達轉一秒就停。先不要把這三個積木放進 `loop`，否則它會不停重複。

按「執行程式」。

**成功訊號**：M1 以低速轉動約一秒，然後停止。看見一次完整動作，就表示你第一次用積木控制到馬達了。

如果接的是其他插槽，將積木中的馬達編號改成對應的 M2、M3 或 M4；一次只測一顆。

## 03　PWM 是出力比例，不是速度命令

把第一個積木的數字從 30 依序改成 10、30、60，再分別執行。每次都只觀察一件事：馬達的起轉與轉動感覺有沒有改變。

PWM 的範圍是 0–100%。`30%` 代表輸出約三成的動力比例，並不代表「固定 30 RPM」。電壓、電池剩餘、摩擦、輪子是否著地與馬達個體差異，都會影響實際轉速。

| 你改的值 | 它代表什麼 | 你可能看到什麼 |
| --- | --- | --- |
| 10% | 很小的出力 | 馬達可能不動、抖動，或勉強起轉。 |
| 30% | 適合第一次測試 | 低速轉動，方便觀察方向。 |
| 60% | 較大的出力 | 轉得更有力，但不保證正好是 30% 的轉速。 |

**成功訊號**：你可以用一個數字控制「明顯更有力」或「明顯較弱」，也知道它不是精準速度設定。

## 04　正負號就是方向

把方向下拉選單從 `Forward` 改成 `Backward`，保持 30%，再執行一次。你應該會看到同一顆馬達朝相反方向轉。

在程式內部，Forward 會變成正的 PWM，Backward 會變成負的 PWM：

```json
{ "cmd": "pwm", "motor": 1, "duty": 30 }
{ "cmd": "pwm", "motor": 1, "duty": -30 }
```

這就是後續所有馬達指令的共同語言：**正負號決定方向，數字大小決定出力比例。**

## 05　為什麼兩顆馬達同樣 30% 卻不一樣？

把同一套測試依序換到兩顆馬達。即使都設 30%，它們也可能聽起來或看起來不一樣快。這是正常現象：馬達、齒輪、接線、摩擦與負載沒有兩套完全一樣。

現在的 PWM 是開迴路：控制板沒有量測每顆馬達實際轉多快，所以無法自動補償差異。之後 M3、M4 的編碼器與速度控制，才會讓系統知道「它實際上轉了多少」。

## 卡住時，從這裡查

| 現象 | 先做什麼 |
| --- | --- |
| 按執行完全沒有反應 | 確認手機仍連著 ESP32 熱點，Blockly 頁顯示 WebSocket 已連線。 |
| 網頁顯示已執行，但馬達不動 | 檢查馬達驅動板的外接電源、共地與該馬達插槽；再回硬體功能檢測頁測試。 |
| 馬達只抖一下或板子重啟 | 通常是馬達電源電流不足，先停止測試並檢查供電。 |
| 馬達方向和預期相反 | 在積木改用 Backward，或在確認接線後交換該馬達的兩條輸出線。 |
| 每次執行都停不下來 | 按 Blockly 的「停止程式」；確認動作放在 `setup`，並且最後有 `停止馬達`。 |
